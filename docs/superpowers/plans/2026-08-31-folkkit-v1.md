# Folkkit V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a bilingual, static, local-first Folkkit V1 whose core PDF, QR, and conversion flows are privacy-verifiable and deployable through a generated Hosttech `plesk` branch.

**Architecture:** Keep the inherited format graph and converter modules, but place them behind a localized release catalog and a hardened runtime. Split the 1,238-line `ConvertPanel` by session, storage, runtime, and presentation responsibilities; all runtime assets stay same-origin and no application backend exists.

**Tech Stack:** React 19, Vite 7, plain CSS, Vitest, Testing Library, Playwright, pdf-lib, qrcode, FFmpeg WASM, Bun, GitHub Actions, PowerShell release scripts.

**Spec:** `docs/superpowers/specs/2026-08-31-folkkit-design.md`

## Global Constraints

- Preserve AGPL-3.0-only, upstream history, attribution, and third-party notices.
- Process user file contents only in browser memory or isolated workers; never place content in URLs, logs, analytics, or default persistent storage.
- Use no runtime origin except the Folkkit origin; fonts, FFmpeg core, workers, WASM, icons, and legal assets are same-origin.
- German and English are complete release languages; untranslated production keys fail verification.
- Visual direction is `Warm Shell / Dark Workbench`, without violet-blue AI glow, neon, generic AI decoration, floating orbs, or ornamental glass.
- Support current and previous stable Chrome, Edge, Firefox, and Safari, including current iOS Safari.
- `main` is full source; `plesk` is generated hosting-only and never edited or force-pushed.
- Do not change repository visibility, register domains, or deploy live without explicit user authorization.
- Before execution, obtain explicit authorization for the planned local commits. Do not push implementation commits unless the user separately authorizes GitHub publication.
- Use `superpowers:test-driven-development` for implementation tasks, `ui-design` for Task 5, `codex-security:security-scan` in Task 11, and `superpowers:verification-before-completion` at every completion gate.

## Planned file structure

- `src/i18n/`: locale dictionaries, provider, interpolation, and completeness checks.
- `src/catalog/`: released-tool metadata, localized categories, release tiers, and stable lookup APIs.
- `src/privacy/`: namespaced preferences, explicit history consent, and content-history storage.
- `src/routing/`: content-free URL parsing and navigation state.
- `src/runtime/`: limits, object-URL lifecycle, worker protocol, cancellation, and tool execution.
- `src/components/shell/`: Folkkit header, footer, navigation, privacy status, and language controls.
- `src/components/workspace/`: focused input, progress, output, error, and download components extracted from `ConvertPanel`.
- `src/pages/`: home, catalog, workspace, privacy, licenses, terms, contact, and source views.
- `src/test/` and `tests/e2e/`: shared fixtures, unit/component coverage, browser journeys, and network assertions.
- `scripts/`: runtime-asset sync, service-worker generation, third-party notice generation, build, and Plesk verification/publishing.
- `hosting/`: reviewed Hosttech `.htaccess` and static hosting contract inputs.
